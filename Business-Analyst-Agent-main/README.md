# Business Analyst Agent

An AI-powered agent that converts a client's project idea into structured software requirements, user stories, acceptance criteria, and documentation using LangGraph, and retrieval-augmented generation (RAG) over a persistent knowledge base.

## How It Works
1. Collects project details (including business case and task breakdown) and suggests missing features.
2. Lets the client customize the UI theme and logo.
3. Retrieves knowledge-base evidence and generates requirements, user stories, and acceptance criteria.
4. Validates the results, flags ambiguous or inconsistent items for review, and allows client feedback.
5. Exports the final deliverables and a canonical, validated copy of the requirements.

## Setup
1. Create and activate a virtual environment.
2. Install dependencies: `pip install -r requirements.txt`
3. (Optional) Ingest the sample knowledge base for RAG: `python scripts/ingest_knowledge_base.py`
4. Run: `python main.py`

## Project Structure
- `main.py` — Application entry point.
- `config/` — Settings and predefined choices.
- `agent/` — LangGraph state, workflow nodes, and routing.
- `services/` — Gemini provider, document generation, RAG (ingestion, vector store, retrieval) and triage rules.
- `knowledge_base/` — Documents indexed for retrieval (demonstration content).
- `scripts/` — `ingest_knowledge_base.py` and `create_user.py`.
- `outputs/` — Generated files. Each run writes to its own folder, `outputs/runs/<run id>/`.

## Output Files
- `requirements.json` — Structured project information for handoff to a Software Architect agent.
- `requirement_analysis.docx` — Detailed requirement analysis.
- `project_requirements.docx` — Project requirements summary.
- `user_stories.docx` — User stories and acceptance criteria.
- `logo_option_1.svg`, `logo_option_2.svg`, `logo_option_3.svg` — Generated logo concepts.
- `logo.svg` — Selected logo.
- `canonical_requirements.json` — The requirements in the validated canonical format, with validation status, flagged items and retrieved evidence.

**EcoTrack sample:** Existing EcoTrack files demonstrate example deliverables; they are not necessarily generated by the current run. Each new run has its own folder under `outputs/runs/`, so earlier runs are never overwritten.

## Design
The project uses modular functions and LangGraph for workflow management, with separate services for LLM calls and document generation. This separation makes the code easier to maintain and extend.
