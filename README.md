# Business Analyst Agent

An AI-powered agent that converts a client's project idea into structured software requirements, user stories, acceptance criteria, and documentation using Gemini, LangGraph, and retrieval-augmented generation (RAG) over a persistent knowledge base.

This file documents the standalone CLI (`python3 main.py`). For the web frontend/backend, Gemini/RAG configuration, and the full repository layout, see the **repository root `README.md`** (one level up from this directory).

## How It Works
1. Collects project details and suggests missing features.
2. Lets the client customize the UI theme and logo.
3. Generates requirements, user stories, and acceptance criteria.
4. Validates the results and allows client feedback.
5. Exports the final deliverables.

## Setup
1. Create and activate a virtual environment.
2. Install dependencies: `pip install -r requirements.txt`
3. Copy `.env.example` to `.env` and add your `OPENROUTER_API_KEY` 
4. (Optional) Ingest the sample knowledge base for RAG: `python3 scripts/ingest_knowledge_base.py`
5. Run: `python3 main.py`

## Project Structure
- `main.py` — Application entry point.
- `config/` — Settings and predefined choices.
- `agent/` — LangGraph state, workflow nodes, and routing.
- `services/` — LLM interaction and document generation.
- `outputs/` — Generated files and sample EcoTrack project deliverables.

## Output Files
- `requirements.json` — Structured project information for handoff to a Software Architect agent.
- `requirement_analysis.docx` — Detailed requirement analysis.
- `project_requirements.docx` — Project requirements summary.
- `user_stories.docx` — User stories and acceptance criteria.
- `logo_option_1.svg`, `logo_option_2.svg`, `logo_option_3.svg` — Generated logo concepts.
- `logo.svg` — Selected logo.

**EcoTrack sample:** Existing EcoTrack files demonstrate example deliverables; they are not necessarily generated by the current run. Files with matching names may be overwritten.

## Design
The project uses modular functions and LangGraph for workflow management, with separate services for LLM calls and document generation. This separation makes the code easier to maintain and extend.
